# تقرير تغطية الاختبارات وعينات Unity المطلوبة

> **حالة التقرير:** مبني على سجلات تشغيل واختبار فعلية محفوظة محليًا في 15 أغسطس 2026. لا يَعد هذا التقرير بأن لعبة أو إصدار Unity غير مذكور في قسم «اختُبر فعليًا» مدعوم أو مُتحقق منه.

## 1. الغرض وحدود الاختبار

يشرح هذا التقرير ثلاثة أمور منفصلة بوضوح: بيانات Unity التي جرى تحميلها واختبارها بالفعل، اختبارات البرنامج الآلية، وعينات الألعاب المصرح بها التي ما زالت مطلوبة لتقييم الاستيراد والتجميع والتصدير عبر أجيال Unity المختلفة. لا يحتاج الاختبار إلى اسم لعبة محدد؛ الأهم هو أن تكون العينة من لعبة أو مشروع يملك صاحبها حق التحليل، وأن تحتوي على نوع الأصول المطلوب.

نسخة **AssetRipper DzGreen Premium** تقبل بيانات Unity النصية أو غير المشفرة بعد تصريح المستخدم الصريح. وهي لا تقبل حاويات مشفرة، أو تفريغات ذاكرة، أو أنظمة ملفات افتراضية خاصة، أو مفاتيح وصول، أو أي مسار يرمي إلى تجاوز ضوابط الحماية. كما أنها لا تخترع Mesh أو Texture أو Script أو ملف وسائط مفقودًا؛ بل تسجله كاعتماد مفقود حتى يبقى التصدير أمينًا للبيانات المتاحة [1].

## 2. ما اختُبر فعليًا

### 2.1 عينة Unity الفعلية الوحيدة التي حُمّلت في اختبار تكامل

| الحقل | القيمة الموثقة |
| --- | --- |
| تسمية العينة | حزمة مرجعية Android؛ اسم اللعبة غير موثق في سجل الاختبار ولا يجب تخمينه |
| إصدار Unity الذي قرأه المستورد | `2020.1.0a0` |
| المنصة | Android |
| صيغة الإدخال | مجلد Unity عادي متعدد الملفات؛ تم تمريره بعد التصريح الصريح فقط |
| ملفات المصدر عند تجهيز العينة | 515 ملف Unity مترابط في مجلد الاختبار؛ لا تتوفر العينة الآن ضمن مساحة العمل لأنها كانت بيانات اختبار مؤقتة |
| Asset Collections بعد الاستيراد | 593 |
| Resource Files بعد الاستيراد | 374 |
| الأصول المصنفة | 274,900 |
| ملفات عزلها المستورد بسبب فشل | 0 |
| حالة التشخيص | نجح مسار `/Assets/PremiumDiagnostics` وأعاد تقرير JSON بعد الاستيراد |

يشمل عدّاد الأصول الفعلي في هذه العينة 4,304 Mesh و4,185 Texture2D و1,563 AnimationClip و1,165 SkinnedMeshRenderer، إلى جانب GameObject وTransform وMaterial وSprite وAnimator. هذا يثبت أن المستورد قرأ مجموعة Android متعددة الملفات، وأن تقرير Premium يحصي العائلات ذات الأولوية من البيانات التي حُمّلت بالفعل. لكنه **لا** يثبت بمفرده أن كل نموذج أو Animation أو صوت أو فيديو من كل لعبة سيُصدر ويُفتح بلا تعديل في Unity أو Blender.

## 3. ماذا تغطي العينة الحالية وماذا لا تغطي

| مجال التحقق | الحالة | الدليل أو القيد |
| --- | --- | --- |
| استيراد Android متعدد الملفات | **اختُبر** | Unity `2020.1.0a0`، 593 Collection و374 Resource File، بلا ملفات معزولة |
| قراءة Mesh وSkinnedMeshRenderer وTexture2D وAnimationClip | **اختُبر على مستوى الجرد** | ظهرت عدّادات فعلية لهذه العائلات في تقرير التشخيص |
| رفض إدخال بلا تصريح | **اختُبر** | يطلب البرنامج `--premium-authorized` قبل التحميل |
| رفض التشفير/الذاكرة/VFS الخاصة | **اختُبر بوحدات السياسة** | محظور صراحة في سياسة الإدخال |
| إعدادات تصدير Premium المحافظة على العلاقات | **اختُبر بوحدات الإعداد** | لا يعالج مراجع أو محتوى غير متاح |
| فتح FBX الناتج في Blender | **غير متحقق بما يكفي** | يلزم نموذج SkinnedMesh محدد وملف قبول Blender |
| فتح مشروع Unity الناتج في إصدار Unity مطابق | **غير متحقق بما يكفي** | يلزم مشروع/لعبة مرجعية ومقارنة للروابط |
| AudioClip، VideoClip، SpriteAtlas فعلي | **غير متحقق بما يكفي** | العينة الحالية لا تثبت نجاح هذه الأنواع من طرف إلى طرف |
| Unity 3.x و4.x و5.x | **غير مختبر بعينة لعبة** | لا توجد عينة محفوظة لهذه الأجيال |
| Unity 2017–2022 LTS | **غير مختبر بعينات منفصلة** | عينة واحدة فقط من 2020.1 alpha |
| Unity 6 | **غير مختبر بعينة لعبة** | مطلوب اختبار Addressables وAssetBundles حديثة |
| iOS وWebGL وLinux وmacOS | **غير مختبر بعينة لعبة** | لا توجد حزم منصة محفوظة |
| محتوى مشفر أو محمي | **خارج النطاق** | لن يُطلب أو يُعالج |

تستحق ملفات الاعتماد اهتمامًا خاصًا: توضح وثائق Unity أن AssetBundle يمكن أن يوزع البيانات المتسلسلة على ملفات موارد منفصلة، وأن تحميل Prefab يعتمد على توفر الحزم التابعة له. لهذا لا يكفي رفع ملف `CAB-*` منفردًا إذا كانت له ملفات أو حزم شقيقة [2].

## 4. ما الألعاب أو المشاريع المطلوبة؟

لا أطلب لعبة بعينها أو عنوانًا تجاريًا محددًا. اختر لعبة أو مشروعًا تملك حق تحليله، ثم طابقه مع صف في المصفوفة التالية. الأولوية ليست لعدد الألعاب بل لتغطية الحالات التي تختلف فيها بنية البيانات: العمر، المنصة، الحزم التابعة، الشخصيات ذات العظام، الرسوم المتحركة، الأطالس، والوسائط.

| الأولوية | فئة اللعبة أو المشروع المطلوب | إصدار Unity المستهدف | سبب الاختبار | الحد الأدنى للنجاح |
| --- | --- | --- | --- | --- |
| P0 | لعبة 3D صغيرة من جيل قديم، فيها شخصية Rigged وحركة واحدة على الأقل | Unity 5.6.x | اختبار التسلسل القديم، Mesh، العظام، وFBX | استيراد بلا مراجع Mesh مفقودة، Prefab قابل للفحص، وFBX يفتح في Blender |
| P0 | لعبة 2D قديمة أو متوسطة فيها SpriteAtlas وواجهة | Unity 2017.4.x أو 2018.4.x | اختبار Sprite/SpriteAtlas والاعتمادات عبر الحزم | صور غير بيضاء، أسماء Sprite صحيحة، وتقطيع Atlas يمكن مراجعته |
| P0 | لعبة Android عادية متعددة حزم المحتوى | Unity 2019.4.x أو 2020.3.x LTS | اختبار `*.assets` و`*.resS` وCAB والتبعيات بين الحزم | لا تظهر رسالة dependency missing عند توفير المجموعة الكاملة |
| P0 | لعبة Windows 3D ذات شخصيات متحركة | Unity 2021.3.x LTS أو 2022.3.x LTS | اختبار Prefab، SkinnedMeshRenderer، AnimatorController، والخامات الحديثة | بنية Prefab متماسكة، Mesh وMaterial وAnimationClip متصلة حيث تكون البيانات متاحة |
| P1 | مشروع أو لعبة تستخدم URP | 2021.3.x أو 2022.3.x | اختبار Material/Texture في مسار عرض حديث | حفظ العلاقات وملفات الخامات، مع تقرير واضح لما لا يمكن استعادته |
| P1 | مشروع أو لعبة تستخدم HDRP | 2021.3.x أو 2022.3.x | اختبار مواد أكبر وتعقيد Shader | عدم انهيار الاستيراد، وخروج تشخيص دقيق للمكونات غير القابلة للتمثيل |
| P1 | مشروع Addressables عادي غير مشفر | Unity 2021.3–2022.3 أو Unity 6 | اختبار catalog والحزم الديناميكية والتبعيات | اكتمال الجرد عند توفير catalog والحزم التابعة معًا |
| P1 | لعبة Unity 6 تحتوي 2D و3D أو Addressables | Unity `6000.0.x` أو أحدث | اختبار آخر جيل من البيانات وTypeTree | تقرير تشخيص كامل واستيراد للبيانات غير المشفرة دون أخطاء عزل غير مبررة |
| P2 | حزمة WebGL مرخصة ومفتوحة البنية | 2019–Unity 6 | اختبار تغليف المتصفح عند توفر بيانات Unity عادية | تقرير واضح بالملفات المقروءة والملفات غير المتاحة، من دون محاولة كسر الحماية |
| P2 | لعبة تتضمن AudioClip وVideoClip داخل بيانات Unity العادية | أي جيل متاح | اختبار مسارات الصوت والفيديو وملفات الموارد المرافقة | توثيق واضح لما يصدر فعليًا وما يظل مرجعًا غير مدعوم |

> توصي Unity باستخدام عينات مبنية من أجيال متعددة لأن أرشيف الإصدارات يمتد من Unity 5 إلى Unity 6، ولأن AssetBundle لا يضمن التوافق الأمامي بين إصدارات المحرك [2] [3].

## 5. الملفات التي يجب رفعها لكل عينة

### 5.1 عينة Windows أو Linux أو macOS Player

ارفع **مجلد البيانات كاملاً** بعد ضغطه، وليس ملفًا مفردًا. يتضمن ذلك عادةً العناصر التالية إن وجدت:

```text
GameName_Data/
  globalgamemanagers
  resources.assets
  sharedassets*.assets
  sharedassets*.resource أو sharedassets*.resS
  level* أو level*.split*
  StreamingAssets/               (إن كان يحتوي AssetBundles عادية)
  Managed/                       (اختياري للتشخيص العام فقط؛ لا يلزم لاستخراج الأصول)
```

إذا كان المحتوى موزعًا في حزم `CAB-*` أو ملفات Bundle، ارفع الحزم الشقيقة كلها مع ملفات `.resS` و`.resource` المطابقة لها. لا تعِد تسمية الملفات ولا تفك ضغط Bundle إلى أجزاء منفصلة؛ أسماء ومسارات الملفات تساعد في حل الاعتمادات.

### 5.2 عينة Android

المطلوب هو **مجلد Unity المصرح به بعد الاستخراج العادي** من التطبيق الذي تملك حق تحليله، ويشمل غالبًا:

```text
assets/bin/Data/
  globalgamemanagers
  resources.assets
  sharedassets*.assets
  *.resS أو *.resource
  Managed/                       (اختياري)
  StreamingAssets/               (إن كان موجودًا)
```

لا نحتاج إلى APK أو AAB كاملاً إذا كان بإمكانك رفع مجلد Data العادي. لا ترسل مفاتيح، أو ملفات ذاكرة، أو تطبيقًا مشفرًا، أو تعليمات لاستخراج محتوى محمي. إن كانت اللعبة تقسم الملفات بين APK وملف توسعة OBB أو حزم إضافية، ضع كل ملفات Unity النصية المصرح بها في بنية مجلدات محفوظة كما هي.

### 5.3 عينات AssetBundle وAddressables

لأن الحزم يمكن أن تعتمد على حزم أخرى، يجب أن تتضمن العينة **كل الحزم التابعة**، لا الحزمة التي يظهر فيها النموذج وحدها. أرفق:

```text
StreamingAssets/
  catalog.json أو catalog.bin             (إن وجد)
  catalog.hash                            (إن وجد)
  كل ملفات bundle/CAB الشقيقة
  كل ملفات .resource و.resS المرافقة
```

تؤكد وثائق Unity أن AssetBundle لا يدير اعتمادات الحزم تلقائيًا عند التحميل، وأن Prefab قد يحتاج Bundle تابعًا حتى تظهر الخامات أو المكونات المرتبطة به [2].

## 6. ترتيب الرفع المقترح

ابدأ بثلاث عينات فقط لتحديد الأخطاء بسرعة بدل رفع ألعاب كثيرة دفعة واحدة:

1. **عينة P0-3D قديمة:** Unity 5.6 أو 2017/2018، شخصية بعظام وAnimation واحدة على الأقل.
2. **عينة P0-Android:** Unity 2019.4 أو 2020.3، مع جميع ملفات Data وStreamingAssets والحزم التابعة.
3. **عينة P0-حديثة:** Unity 2021.3 أو 2022.3، لعبة Windows تحتوي Prefab وSkinnedMeshRenderer وAnimator وTexture/Material.

بعد نتائج هذه العينات، تكون الأولوية لـ Unity 6 Addressables ثم 2D SpriteAtlas ثم Audio/Video. أرفق مع كل ZIP ملف نصي صغير باسم `sample-info.txt` ولا يحتوي أسرارًا، وفق القالب الآتي:

```text
Sample label: مثال-2022-Windows-Character
Platform: Windows / Android / Linux / macOS / WebGL
Unity version: إن كانت معروفة
Content type: 3D character / 2D atlas / Addressables / audio / video
Expected assets: مثال: شخصية واحدة، 3 Animations، 5 Textures
Known issue to reproduce: مثال: dependency wasn't found أو FBX لا يفتح في Blender
Authorization: أؤكد أن لدي حق اختبار هذه البيانات غير المشفرة.
```

## 7. ما الذي سيفحص لكل عينة

سيُسجل الاختبار بطريقة قابلة للمراجعة: إصدار Unity الذي يحدده المستورد، عدد Collections وResources، أية ملفات معزولة، أصول Mesh/SkinnedMeshRenderer/Texture2D/Sprite/AnimationClip/AudioClip/VideoClip، ونتيجة التصدير. بالنسبة لعينة 3D، ستكون اختبارات القبول هي: حفظ Transform hierarchy، ربط Mesh وMaterial، وجود العظام وBind Pose عند توفرها، والتأكد من قابلية فتح FBX الناتج في Blender. وبالنسبة لعينة Unity Project، سيكون القبول عبر فتح المشروع في إصدار Unity مناسب ومراجعة المراجع المفقودة بدل افتراض استعادة سكربتات أو Shaders غير موجودة في البيانات.

## 8. الخلاصة العملية

الاختبار الفعلي الحالي قوي من ناحية **استيراد Android متعدد الملفات وقراءة جرد كبير من Unity 2020.1**، إضافة إلى 517 اختبارًا آليًا. لكنه لا يكفي بعد لإعلان دعم شامل للأجيال القديمة أو Unity 6 أو كل المنصات أو كل أنواع الأصول. أفضل رفع تالٍ هو ثلاثة ملفات مضغوطة مرخصة تمثل: شخصية 3D قديمة، Android 2019/2020 متعدد الحزم، وشخصية 3D حديثة 2021/2022. عند وصولها، يمكن تحويل كل نتيجة إلى حالة قبول أو عيب محدد ومصلح قابل للتحقق.
